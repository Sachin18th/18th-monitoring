# KPI Monitoring Platform — Requirements & Demo Deployment Guide

> Everything needed to run this project on a fresh **demo location** (server/VM).
> Generated by analyzing the full monorepo (`apps/*`, `packages/*`, `services/*`).

---

## 1. What this project is

A **monorepo** (npm workspaces) for an e-commerce KPI / RUM monitoring platform.

| Workspace | Type | Purpose |
|-----------|------|---------|
| `apps/api` | Fastify 4 + TypeScript | Backend REST API, ingest endpoints, tracker script |
| `apps/dashboard` | Next.js (App Router) + React 19 | Frontend dashboard UI |
| `apps/synthetic-agent` | Node + Playwright | Synthetic monitoring / browser checks (cron) |
| `apps/config-manager` | Node/TS | Config management service |
| `packages/db` | Prisma 5 + PostgreSQL | DB schema, migrations, seeders |
| `packages/ui` | tsup (React) | Shared design-system components |
| `packages/rum-sdk` / `packages/tracker` | tsup (browser IIFE) | Frontend telemetry / storefront tracker |
| `packages/connectors`, `connector-framework`, `events`, `cache`, `config`, `shared-types`, `sdk-core`, `sdk-react` | libraries | Shared logic |

## 2. System prerequisites (install on the demo host)

| Requirement | Version | Notes |
|-------------|---------|-------|
| **Node.js** | **20.19.x** (LTS) | matches dev env (`v20.19.5`) |
| **npm** | **10.x** (`10.8.2`) | workspaces support required |
| **PostgreSQL** | **14+** | primary datastore (Prisma `provider = "postgresql"`) |
| **Git** | any recent | clone the repo |
| **Docker + Docker Compose** | optional | only if deploying via `infra/docker-compose*.yml` |

Playwright (used by `synthetic-agent`) needs system browser libraries:
```bash
npx playwright install --with-deps chromium
```

> The production compose file (`infra/docker-compose.prod.yml`) also references **Kafka** and **ClickHouse** — these are part of the larger production architecture and are **NOT required for a demo**. PostgreSQL alone is enough to run the dashboard + API demo.

## 4. Environment variables

### `apps/api/.env`  (copy from `.env.example`)
```env

NODE_ENV=production

# Auth
JWT_SECRET=<64+ char random string>
JWT_EXPIRES_IN=8h

# PostgreSQL
DATABASE_URL=postgresql://user:password@localhost:5432/kpi_monitoring
DATABASE_POOL_MIN=2
DATABASE_POOL_MAX=10

# Cache TTLs (seconds)

CSV_MAX_MB=10

DLQ_MAX_ATTEMPTS=5

# Rate limiting

RATE_LIMIT_INGEST_WINDOW_MS=60000
RATE_LIMIT_ADMIN_MAX=100
RATE_LIMIT_ADMIN_WINDOW_MS=60000

# Optional (uncomment in real prod): REDIS_URL, SECRET_MANAGER, AWS_REGION,

```

### `apps/dashboard/.env.local`
```env
# Point to the deployed API. For demo on one host:
NEXT_PUBLIC_API_URL=http://localhost:4000
# (use the public URL/IP of the demo box when accessing from a browser)
```

### `packages/db/.env`
```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/KPI?schema=public"
```

> Keep `DATABASE_URL` consistent between `apps/api/.env` and `packages/db/.env`.
> **Never commit `.env` files.**

## 5. Demo deployment — step by step

```bash
# 0. Prereqs: Node 20.19.x, npm 10.x, PostgreSQL 14+ running

# 1. Clone & install (installs all workspaces)
git clone <repo-url> && cd "kpi monitoring"
npm install

# 2. Configure env files
cp apps/api/.env.example       apps/api/.env
cp apps/dashboard/.env.example apps/dashboard/.env.local
cp packages/db/.env.example    packages/db/.env
#   -> edit DATABASE_URL, JWT_SECRET, NEXT_PUBLIC_API_URL

# 3. Database: create DB, generate client, run migrations
#    (create the database named in DATABASE_URL first, e.g. `createdb KPI`)
npm run db:generate       --prefix packages/db
npm run db:migrate:deploy --prefix packages/db   # applies all Prisma migrations
npm run seed:auth         --prefix packages/db   # optional: seed demo/auth users

# 4. Build shared packages + apps
npm run build             # builds all workspaces

# 5a. DEV / quick demo (API + dashboard together)
npm run dev               # concurrently runs dev:api + dev:dashboard

# 5b. PRODUCTION-style start
npm run start --prefix apps/api          # node dist/server.js  (port 4000)
npm run start --prefix apps/dashboard    # next start           (port 3000)

# 6. (Optional) synthetic monitoring agent
npx playwright install --with-deps chromium
npm run synthetic:run

# 7. (Optional) seed demo data over HTTP
npm run demo:seed
```

**Ports:** API → `4000`, Dashboard → `3000`. Open `http://<demo-host>:3000`.

## 6. Alternative: Docker Compose

```bash
# Dev:
docker compose -f infra/docker-compose.yml up -d

# Prod-style (includes Kafka + ClickHouse — heavier, not needed for a simple demo):
docker compose -f infra/docker-compose.prod.yml up -d --build
```
Dockerfiles: `infra/docker/Dockerfile.api`, `Dockerfile.dashboard`, `Dockerfile.worker`.
Terraform (AWS ECS/VPC/RDS) lives in `infra/terraform/` for full cloud deploys.

## 7. Demo go-live checklist

- [ ] Node 20.19.x + npm 10.x + PostgreSQL 14+ installed
- [ ] `npm install` completed at repo root
- [ ] All three `.env` files created and filled (DB URL + JWT_SECRET set)
- [ ] Database created; `db:migrate:deploy` ran successfully
- [ ] (Optional) `seed:auth` ran so you can log in
- [ ] `npm run build` succeeds
- [ ] API reachable on `:4000`, dashboard on `:3000`
- [ ] `NEXT_PUBLIC_API_URL` points to the demo host's public address
- [ ] Firewall/security group allows ports 3000 (and 4000 if API hit from browser)
- [ ] Playwright browsers installed (only if running synthetic-agent)
